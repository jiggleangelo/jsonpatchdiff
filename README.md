# JSONPatchDiff

Original MIT browser tool written by AI agents at Manykiln. Open index.html directly; the folder is independently usable. No dependencies, installation, build, CDN, analytics, storage or application network APIs. Compute, apply, test, inversion, structural inspection and JSON downloads all run locally. The page never overwrites either input document when applying a patch. Text is inserted using textContent, never HTML parsing.

Paste original and target JSON, choose a strategy and Compute. The editable patch box receives the generated RFC 6902 patch. Apply & test evaluates that box against Original JSON. Build inverse evaluates the same transaction and shows its inverse without modifying either input. Download JSON writes a local JSON envelope with patch, resulting document, root existence and inverse. To use the patch with an RFC 6902 consumer, take the `patch` array from the envelope. To restore a result, apply `inverse` to that result. Inversion requires the original document; inverse is not inferred from a patch alone. Failed operations clear the previous result and disable export.

Two precisely labelled strategies, so no result is called “minimal” without saying in which sense:

- Structural: preserve shared object/array containers; emit member removals/additions and recursively changed values. Arrays use dynamic programming with minimal insertion/deletion/recursive-substitution cost per alignment. No inferred move/copy, whole-container collapse or global six-operation optimum is claimed. Different equal-cost alignments can produce different correct patches.
- Fewest RFC operations: globally minimal operation count, zero if equal and one otherwise, since replacing the root is permitted. Prefer a focused one-operation structural patch if available; otherwise replace the root. This can create a larger serialized patch while minimizing operation count.

All six operations are accepted: add, remove, replace, move, copy, test. Paths/from are RFC 6901 string pointers: empty string is root, `/` selects an empty key, `~0` decodes tilde, `~1` decodes slash, in that order of semantics (`~01` is literal `~1`). Malformed escapes fail; URI fragments/percent decoding are not accepted as pointer syntax. Object member names including `__proto__`, `constructor`, empty strings, unicode and literal percent sequences are handled as ordinary own properties. Traversal never walks inherited properties.

Array indices are canonical nonnegative decimal integers without leading zeros. Add permits index equal to array length or `-`; remove/replace/test/from require an existing value, so `-` is not a readable index. Move removes first, then resolves its destination, including shifted array indices. Moving into a proper descendant fails; a valid same-location move is a no-op. Copy deep-clones its source. Add to an existing object member replaces it; add never creates missing parents. Test uses exact JSON structural equality: object key order irrelevant, array order significant, JSON number value significant. Unrecognized operation members are ignored as RFC 6902 requires; unsupported operation names are refused.

Atomicity: a transaction uses a private deep clone. Any malformed op, missing path, failed test, invalid index or exceeded resource bound rejects the entire operation list and returns no intermediate document or inverse. Inputs are unchanged on success and failure. Inverse groups restore the exact before-state in reverse order; overwritten values are captured. Inverses may use root replacement and are validated during construction.

Root removal is supported: `exists:false, document:null` means an absent root, not JSON null. Further non-root operations against absence fail; root add can create a new document. An inverse for root removal begins with root add and restores from the null placeholder. If exchanging only a raw document value, preserve `exists` separately to distinguish absence from null.

Input limits: one million characters per parsed JSON value, depth 64, 50,000 visited values and 1,000 patch/inverse operations; cumulative inverse JSON also limited to one million characters. Structural diff budget totals 50,000 DP cells across recursive array comparisons; over-budget structural work is refused, with Fewest operations as an explicit alternative. Diff display permits 2,000 change rows; an oversize display is refused rather than silently truncated. Missing/empty/malformed JSON, nonfinite numbers and non-JSON JS API values (cycles, dates, accessors, sparse arrays, symbols, undefined) are refused. JSON.parse follows JavaScript number precision; supply precision-sensitive identifiers/decimals as strings. Duplicate object member names follow JSON.parse last-member-wins behavior. This is an in-memory JSON data inspector, not a lossless text/number/duplicate-key parser.

Structural inspection compares array positions by index, independently of patch alignment; shifted array values can therefore produce more display rows than patch operations. Rows distinguish absent from JSON null through explicit added/removed/changed labels. All keys, paths and values, including HTML/script text, remain data. There is no file write, SQL, shell or code evaluation.

Run `node --test` in this folder. RFC prose consulted: https://www.rfc-editor.org/rfc/rfc6901 and https://www.rfc-editor.org/rfc/rfc6902 (documentation references only; the application never loads them). No implementation code was copied.
